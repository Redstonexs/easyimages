1. 请将所有文件赋予`0755`和`www`权限
2. 对`PHP`不太熟悉的请不要将图床程序放置于二级目录
3. 请关闭防跨站或删除域名文件夹内的`user.ini`文件 如`宝塔面板`|`军哥lnmp`
4. 网站域名与图片域名必须填写，如果只有一个域名请填写成一样的
5. 首次使用会执行安装程序并并在`config`目录生成`install.lock` 跳过安装流程请删除`install`目录
6. 首次访问首页会检查环境并在`config`目录下生成`EasyImage.lock`
7. 可以使用谷歌浏览器的调试模式查看错误`F12->console`
8. 提示 `upload File size exceeds the maximum value` 调整`PHP`上传大小
9. 提示 `undefined function imagecreatefromwebp()`GD没安装webp, 以此类推
10. 提示 `Warning: is_dir(): open_basedir restriction in effect`解决方法同`3`
11. 无法上传/访问/不显示验证码: 1. 权限问题见问题`1` 2. CDN缓存了 3. 防火墙拦截
12. 宝塔或者其他环境安装成功但是上传失败，多数原因是防火墙拦截上传，取消拦截即可
13. `Fatal error: Allowed memory size......`主机内存或分配给PHP的内存不够 解决方法百度
14. 开启原图保护功能后打开图片链接显示`404`是因为`nginx`或`Apache`页面缓存导致的,`Nginx`解决办法:
```Nginx
# 把Nginx这段配置删掉
location ~ .*\.(gif|jpg|jpeg|png|bmp|swf)$
{
    expires      30d;
    error_log /dev/null;
    access_log /dev/null;
}
```
15. 后台设置页面显示不全: 关闭环境自检或下载并命名为[version.json](https://api.github.com/repositories/188228357/releases/latest)到`admin/logs/version/`目录
16. 开启OPcache后更新文件或者更新版本号可能不生效,重启PHP即可

## Go版本常见问题

### Q: Go版本与PHP版本有什么区别？

A: Go版本具有以下优势：
- 更高性能，响应更快
- 更低资源占用（内存、CPU）
- 单二进制文件部署，无需PHP环境
- 官方Docker镜像支持
- 原生并发支持

### Q: 如何从PHP版本迁移到Go版本？

A: 请参考详细的迁移指南：[从PHP迁移到Go版本](从PHP迁移到Go版本.md)

主要步骤：
1. 备份PHP版本的config目录和i目录
2. 使用转换工具将PHP配置转为JSON
3. 编译并运行Go版本

### Q: Go版本的配置文件格式是什么？

A: Go版本使用JSON格式的配置文件（config/config.json），可以使用转换工具从PHP配置自动转换。

```bash
cd cmd/php2json
go build -o php2json
./php2json ../../config/config.php ../../config/config.json
```

### Q: Go版本支持哪些图片格式？

A: 与PHP版本相同，支持：jpg, jpeg, png, gif, bmp, webp, ico, jfif, tif, tga, svg

### Q: Go版本如何部署？

A: 有三种部署方式：
1. 直接运行：`go build -o easyimage && ./easyimage`
2. Docker部署：`docker build -t easyimage . && docker run -d -p 8080:8080 easyimage`
3. Docker Compose：`docker-compose up -d`

### Q: Go版本的API接口是否兼容？

A: 完全兼容，API端点和响应格式与PHP版本一致。

### Q: Go版本的图片路径是否兼容？

A: 完全兼容，图片URL格式保持一致：`http://domain.com/i/2024/01/01/xxx.jpg`

### Q: Go版本的密码是否兼容？

A: 完全兼容，使用相同的SHA256哈希方式，PHP版本的密码可以直接使用。

### Q: Go版本如何更新？

A: 
```bash
# 直接运行版本
git pull
go build -o easyimage
pkill easyimage
./easyimage

# Docker版本
docker-compose down
docker-compose up -d --build
```
